# وين طلبي؟ — تطبيق تتبّع طلبات «وصّل»

تطبيق Flutter عربي (RTL) يتيح لزبائن «وصّل» متابعة طلباتهم دون الاتصال بالدعم، ويعمل بسلاسة حتى عند ضعف الإنترنت أو انقطاعه.
الحالة والتنقل وحقن الاعتماديات والترجمة كلها عبر **GetX**.

- دليل الهوية البصرية: [docs/BRAND.md](docs/BRAND.md)
- الرموز البرمجية للهوية (المرجع الوحيد): [lib/core/constants/brand_tokens.dart](lib/core/constants/brand_tokens.dart)

## التشغيل

```bash
flutter pub get
flutter run                 # Android / iOS
flutter test                # 20 اختبارًا: نماذج، مستودع، خط زمني، تنسيق، واجهة
flutter analyze             # No issues found
```

اختياري: لتفعيل زر «اطلب الآن» في الحالة الفارغة ليفتح تطبيق الطلب الرئيسي:

```bash
flutter run --dart-define=ORDER_NOW_URL=https://your-store-link
```

### تجربة سيناريوهات عدم الاتصال

| السيناريو | الخطوات | المتوقع |
|---|---|---|
| أول تشغيل متصل | شغّل التطبيق | هيكل تحميل، ثم القائمة وشريط أخضر «متصل — آخر تحديث: الآن» |
| تشغيل دون اتصال مع كاش | فعّل وضع الطيران، ثم أعد فتح التطبيق | القائمة المحفوظة فورًا مع الشريط الكهرماني «أنت غير متصل» |
| تشغيل دون اتصال وبلا كاش | امسح بيانات التطبيق، ثم شغّله في وضع الطيران | حالة خطأ داخل الصفحة مع زر «إعادة المحاولة»، ولا نافذة منبثقة |
| سحب للتحديث دون اتصال | اسحب القائمة للأسفل | SnackBar هادئ، والقائمة تبقى كما هي |
| عودة الاتصال | أطفئ وضع الطيران | «عاد الاتصال — جارِ التحديث…» ثم يختفي الشريط الكهرماني |
| التفاصيل دون اتصال | افتح أي طلب في وضع الطيران | كل التفاصيل متاحة، مع ملاحظة «هذه آخر حالة محفوظة» |

> **في وضع التطوير**: الضغط المطوّل على شعار «وصّل» في الشريط العلوي يحاكي انقطاع الاتصال دون وضع الطيران (مفيد على المحاكي).

## البنية

```
lib/
├── main.dart
├── app/            bindings · routes · theme · translations
├── core/           constants (brand_tokens, app_config) · errors · network · storage
│                   services (feedback) · utils (formatters) · widgets · ui (material barrel)
├── data/           models · sources (remote / local) · repositories
└── modules/
    ├── orders/        bindings · controllers · views (+ widgets)
    └── order_detail/  bindings · controllers (+ delivery_progress) · views (+ widgets)
```

حدود الطبقات: الواجهة لا تعرف SharedPreferences ولا rootBundle، والـ Controller لا يعرف Widget ولا BuildContext، والمستودع لا يعرف GetX ولا الواجهة.

## القرارات التقنية

**المصدر البعيد (Remote).** لا يوجد خادم حقيقي، فالملف `assets/data/orders.json` يمثّل الخادم. لكن `AssetOrderRemoteSource` يتصرف كطلب شبكة حقيقي:

- يفشل بـ `OfflineException` إذا لم يوجد اتصال فعلي.
- فيه زمن استجابة (1.2 ثانية) ومهلة انتظار.
- يزيح كل التواريخ بحيث يكون أحدث طلب «الآن»، فيبقى العرض حيًا («اليوم» و«أمس» والوقت المتوقع) أيًا كان تاريخ التشغيل.

استبداله بـ API حقيقي يعني تنفيذ الواجهة `OrderRemoteSource` فقط.

**Stale-While-Revalidate.** `OrderRepository` يقرأ الكاش أولًا. `OrdersController.loadInitial` يرسم الكاش فورًا، ثم يجدّد من الشبكة في الخلفية مع شريط تقدم رفيع. عند الفشل يُعاد الكاش مع `refreshError`، فلا تُمسح البيانات أبدًا. الطلبات المتزامنة (سحب، زر، عودة اتصال) تُدمج في طلب واحد.

**كشف الاتصال الفعلي.** `connectivity_plus` يكشف الواجهة فقط (واي فاي أو بيانات)، والجهاز قد يكون متصلًا بواي فاي بلا إنترنت. لذلك يُؤكَّد كل تغيير باستعلام DNS خفيف.

**التخزين.** `SharedPreferencesAsync` لا يحتاج تهيئة في `main()`. الكاش وثيقة JSON واحدة بمفتاح عليه رقم إصدار (`orders_cache_v1`)، والكاش التالف يُحذف بدل أن يوقف التطبيق.

**الاستثناءات.** `OfflineException` و`ParsingException` و`ServerException` و`CacheException` تتحول في `UiError` إلى نصوص عربية ودّية. لا يظهر للمستخدم أي استثناء خام، ولا يوجد catch صامت.

**Material و GetX.** Flutter 3.47+ يعلّم `package:flutter/material.dart` كمهجور لصالح `material_ui`. لكن GetX مبني على الأول، والحزمتان تعرّفان أنواعًا منفصلة (مثل `ThemeData`)، فخلطهما يكسر الأنواع. لذلك تستورد كل الملفات Material عبر ملف واحد هو [lib/core/ui/material.dart](lib/core/ui/material.dart) فيه الاستثناء الوحيد الموثّق. الترحيل لاحقًا يعني تعديل هذا الملف فقط.

**التنقل.** `Transition.cupertino` بمدة 300ms ومنحنى `easeOutCubic`. في RTL تدخل الصفحة من اليسار، ويعمل السحب من الحافة للرجوع. القائمة تبقى في المكدس مع `PageStorageKey`، فيُحفظ موضع التمرير ولا يحدث جلب جديد عند الرجوع.

## قرارات التصميم

- **نص كحلي على الزر التيل**: الأبيض على التيل `#2CB99A` تباينه 2.47:1 ويفشل في WCAG، والكحلي `#073F5D` يعطي 4.53:1 ويجمع لوني الهوية. والنص التيل على الخلفية الفاتحة يستخدم `#14735C` (5.39:1).
- **كل الأسماء والأرقام والعملة في ملف واحد**: [lib/core/constants/app_content.dart](lib/core/constants/app_content.dart).
- **لكل حالة ثلاث درجات**: Base للأيقونة، وFg للنص بتباين ≥ 4.5:1، وBg للخلفية الفاتحة. والحالة لا تُعرف باللون وحده، فالأيقونة والنص حاضران دائمًا.
- **الخط مضمّن** (IBM Plex Sans Arabic بأوزان 400 و500 و600 و700) ليظهر صحيحًا من أول تشغيل دون إنترنت.
- **الأرقام لاتينية** مع أسماء عربية للشهور والأيام، وصيغ جمع عربية صحيحة («منذ دقيقتين» و«منذ 5 دقائق» و«منذ 25 دقيقة»). رقم الطلب يُعرض LTR معزولًا حتى لا تنتقل «#» إلى نهايته.
- **لا أزرار ميتة**: زر المندوب يظهر فقط إذا وُجد رقمه والطلب غير منتهٍ. وزر «اطلب الآن» إما يفتح رابطًا مُعدًّا أو يوضح أن الطلب يتم من تطبيق «وصّل» الرئيسي.
- **الشريط الكهرماني يختفي إذا لم يوجد كاش**، لأن عبارة «تُعرض آخر قائمة محفوظة» ستكون كاذبة حينها، وحالة الخطأ داخل الصفحة تشرح الموقف.

## الإضافات المنفّذة

الوضع الداكن (`ThemeMode.system`) · تحديث «آخر تحديث» كل دقيقة (`Timer.periodic` يُلغى في `onClose`) · نسخ رقم الطلب والعنوان مع اهتزاز خفيف وSnackBar · مؤشر تحديث رفيع في الخلفية · معالجة الطلب الملغي (مراحل حتى الإلغاء ثم نقطة حمراء وسبب الإلغاء) · حفظ موضع التمرير · أيقونة التطبيق لأندرويد وiOS والويب · اسم التطبيق «وصّل» وصلاحيات الشبكة واستعلام `tel:`.
